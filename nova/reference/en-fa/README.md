# Nova English→Persian Reference Layer

This directory is the production authoring reference layer for `en-fa`.
It is **not** the runtime database and it is not a second canonical Lesson source.

The sync pipeline pins upstream revisions, merges sense-specific Openjam Persian data with CEFR-J / Octanove level evidence, applies Nova quality gates, and writes level snapshots under `lexical/` plus grammar profiles under `grammar/`.

## Authority / precedence

- Lesson source remains canonical: `nova/courses/en-fa/lessons/*/lesson.source.json`.
- CEFR placement uses exact `(lemma, POS)` evidence before lemma-only consensus.
- CEFR-J / Octanove evidence overrides Openjam's frequency-derived CEFR band when available.
- Openjam supplies lemma, frequency, English sense, Persian sense translation and topic tags.
- Records scoring below 90 remain available for review but are not `productionEligible`.
- A frequency-only Openjam CEFR fallback is reference/review data, not a production curriculum decision.
- `curriculumEligible` means the level placement has acceptable CEFR evidence.
- `productionEligible` means the complete lexical record also passes Nova's quality threshold.
- External data never auto-publishes a Lesson. It constrains and supports authoring/QA.

## Generated files

`manifest.json`, `lexical/*.json`, `grammar/*.json`, and `lesson_coverage.json` are generated by:

```bash
python nova/_assistant/content-system-v1/tools/sync_reference_data.py --repo-root .
python nova/_assistant/content-system-v1/tools/validate_reference_data.py --repo-root . --strict
python nova/_assistant/content-system-v1/tools/audit_lesson_reference_coverage.py --repo-root .
```

Do not hand-edit generated snapshots. Update `sources.lock.json` or the merger, then re-sync.

## Production authoring queries

Content-authoring tools consume the committed snapshot through `reference_catalog.py`; they do not fetch upstream data during Lesson generation.

Get five high-confidence A1 food candidates:

```bash
python nova/_assistant/content-system-v1/tools/reference_catalog.py \
  --repo-root . --level A1 --topic food --limit 5 --recommend
```

Look up a specific lexical item:

```bash
python nova/_assistant/content-system-v1/tools/reference_catalog.py \
  --repo-root . --level A1 --lemma name --pos noun --limit 20
```

Select new vocabulary while excluding already-taught lemmas:

```bash
python nova/_assistant/content-system-v1/tools/reference_catalog.py \
  --repo-root . --level A1 --topic drink --recommend --limit 6 \
  --exclude water --exclude coffee
```

By default queries return only `productionEligible` records. `--include-review` is an explicit author/research escape hatch and must not be used to bypass the Lesson quality gate.

## Lesson coverage semantics

The coverage audit distinguishes:

- `exact_match`: lemma + POS agree with reference evidence; production sense evidence may be used when eligible.
- `lemma_only_match`: useful curriculum evidence exists for the lemma, but POS/sense differs; it must not auto-replace the authored Lesson meaning.
- `unmatched`: no current reference evidence exists.
- multiword expressions remain Nova-authored units unless a later reference source explicitly models them.
