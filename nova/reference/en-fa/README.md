# Nova English→Persian Reference Layer

This directory is the production authoring reference layer for `en-fa`.
It is **not** the runtime database and it is not a second canonical Lesson source.

The sync pipeline pins upstream revisions, merges sense-specific Openjam Persian data with CEFR-J / Octanove level evidence, applies Nova quality gates, and writes level snapshots under `lexical/` plus grammar profiles under `grammar/`.

It also supports a separately generated, compressed `dialogue/` snapshot. Taskmaster and Schema-Guided Dialogue supply learner-visible English source material that can be copied verbatim into new Lessons with full provenance and license metadata. Dialogue source data supports authoring; canonical Lesson JSON remains the only Lesson source of truth.

## Authority / precedence

- Lesson source remains canonical: `nova/courses/en-fa/lessons/*/lesson.source.json`.
- CEFR placement uses exact `(lemma, POS)` evidence before lemma-only consensus.
- CEFR-J / Octanove evidence overrides Openjam's frequency-derived CEFR band when available.
- Openjam supplies lemma, frequency, English sense, Persian sense translation and topic tags.
- Records scoring below 90 remain available for review but are not `productionEligible`.
- A frequency-only Openjam CEFR fallback is reference/review data, not a production curriculum decision.
- Conflicting CEFR evidence is never `curriculumEligible` or `productionEligible` until resolved.
- `curriculumEligible` means the level placement has acceptable, unambiguous CEFR evidence.
- `productionEligible` means the complete lexical record also passes Nova's quality threshold.
- Open dialogue records preserve exact source English plus source dialogue ID, file, pinned commit, license and attribution.
- External data never auto-publishes a Lesson or blindly overwrites an authored sense/translation. It constrains and supports authoring/QA.

## Generated lexical / grammar files

`manifest.json`, `lexical/*.json`, `grammar/*.json`, and `lesson_coverage.json` are generated by:

```bash
python nova/_assistant/content-system-v1/tools/sync_reference_data.py --repo-root .
python nova/_assistant/content-system-v1/tools/validate_reference_data.py --repo-root . --strict
python nova/_assistant/content-system-v1/tools/audit_lesson_reference_coverage.py --repo-root .
```

Do not hand-edit generated snapshots. Update `sources.lock.json` or the merger, then re-sync.

## Open dialogue snapshot

The direct-copy dialogue layer is generated independently so large corpora are downloaded only when the pinned source fingerprint changes:

```bash
PYTHONPATH=nova/_assistant/content-system-v1/tools \
python nova/_assistant/content-system-v1/tools/sync_open_dialogue_corpus.py \
  --repo-root . --course en-fa

PYTHONPATH=nova/_assistant/content-system-v1/tools \
python nova/_assistant/content-system-v1/tools/validate_open_dialogue_corpus.py \
  --repo-root . --course en-fa
```

Generated files live under `dialogue/`:

- `manifest.json` records source locks, input hashes, counts and shard hashes;
- `index.jsonl` provides lightweight authoring metadata for every source dialogue;
- `shards/*.jsonl.gz` contains complete normalized records with exact source turn text;
- `ATTRIBUTION.md` records upstream attribution and licenses.

The importer does not strip, grammar-correct, paraphrase or normalize punctuation in source turn text. Exact duplicates remain in the corpus for source completeness but are linked with `duplicateOf` and are not proposed twice for production authoring.

For production parallel authoring, plan with:

```bash
python nova/_assistant/content-system-v1/tools/open_corpus_wave.py \
  --repo-root . \
  --config nova/curriculum/en-fa/factory.config.json \
  --workspace-dir nova/curriculum/en-fa \
  --workers 8
```

This wraps the existing `factory_wave` planner, keeps its curriculum/story authority, and adds different verbatim dialogue candidates to each worker packet. The selected source is persisted under `lesson.metadata.openCorpus`.

## Production authoring queries

Content-authoring tools consume the committed snapshot through `reference_catalog.py`; they do not fetch upstream data during Lesson generation.

Get five high-confidence A1 food candidates:

```bash
python nova/_assistant/content-system-v1/tools/reference_catalog.py \
  --repo-root . --level A1 --topic food --limit 5 --recommend
```

Look up a specific lexical item:

```bash
python nova/_assistant/content-system-v1/tools/reference_catalog.py \
  --repo-root . --level A1 --lemma name --pos noun --limit 20
```

Select new vocabulary while excluding already-taught lemmas:

```bash
python nova/_assistant/content-system-v1/tools/reference_catalog.py \
  --repo-root . --level A1 --topic drink --recommend --limit 6 \
  --exclude water --exclude coffee
```

By default queries return only `productionEligible` records. `--include-review` is an explicit author/research escape hatch and must not be used to bypass the Lesson quality gate.

## Lesson 21+ production gate

The reference layer becomes a blocking build dependency for new English→Persian Lessons starting at `sortOrder: 21`.

- every `target` lexical item with `itemType: word` must have an exact lemma + POS match at the Lesson level;
- that reference record must be both `curriculumEligible` and `productionEligible`;
- the authoring step must choose the intended sense and store its stable `referenceKey` in `lexicalItem.metadata.referenceKey`;
- the stored `referenceKey` must resolve to one of the exact production-eligible candidates for that lemma + POS + level;
- an authored context-specific Persian meaning may differ from the selected reference translation, but that difference is explicitly warned for review rather than silently replacing either value;
- review/support language is audited but is not blocked by this forward-only target gate;
- multiword expressions/formulas remain Nova-authored units and are not forced into a single-word dictionary model;
- Lessons 1–20 are audited but are not retroactively invalidated.

`build_pilot.py` writes `reference_validation.json` beside each canonical Lesson. A failing enforced target prevents the Lesson from reaching paid audio generation, SQL compilation or runtime import.

Scheduled/reference-source syncs also validate every canonical Lesson before committing a changed snapshot, so an upstream data change cannot silently invalidate a Lesson 21+ target.

## Dialogue licensing gate

Dialogue sources are accepted only when their license appears in `dialogueLicensePolicy.approvedLicenses` in `sources.lock.json`.

- Taskmaster-1 is pinned as `CC-BY-4.0` and may be reused with attribution.
- Schema-Guided Dialogue is pinned as `CC-BY-SA-4.0`; Nova keeps its learner-visible English verbatim by default and retains the ShareAlike provenance requirement for any adaptation.
- Tatoeba remains sentence/collocation evidence with the per-sentence license retained in its usage snapshot.
- Unknown dialogue licenses fail the corpus sync rather than entering worker packets silently.

## Lesson coverage semantics

The coverage audit distinguishes:

- `exact_match`: lemma + POS agree with reference evidence; production sense evidence may be used when eligible.
- `lemma_only_match`: useful curriculum evidence exists for the lemma, but POS/sense differs; it must not auto-replace the authored Lesson meaning.
- `unmatched`: no current reference evidence exists.
- multiword expressions remain Nova-authored units unless a later reference source explicitly models them.
